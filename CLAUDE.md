# Project notes for Claude

Dugout: a pixel-art football manager-card game (see README.md; the name is in data/project.csv). Design source of truth: the Claude Docs document
"Pixel Football Card Game - Design Document" (https://claude.ai/code/artifact/0d90f732-ad07-4972-8473-3f28f323153c),
summarised in docs/DECISIONS.md.

## Rules of engagement with the user
- Brainstorm first and write decisions into the design doc; put a checkpoint before each new stage. Godot is allowed now (user said go): the project is in godot/. Still ask before other big builds.
- Keep replies short and plain. Do not over-explain on card faces or in the UI.
- Data lives in CSVs under data/ and is loaded by the game at runtime, so keep columns stable and values tweakable.

## Conventions
- Sprite scripts import each other as top-level modules; run them from `sprites/`.
- Pitch coordinates: x 0-100 left to right, y 0-100 own goal to opponent goal.
- Roles: GK, CB, LB, RB, CDM, CM, CAM, LW, RW, ST. Outfield stats PAC SHO PAS DRI DEF PHY, keeper stats REF HAN POS.

## Card design (decided)
Use the cards/cardlib2.py face: slot number, category, illustrated emblem, name plate, success / risk / cooldown. No effect text on the card;
the description shows in the hover tooltip (cardlib2.popup). All 200 emblems drawn (cards/recipes.py + cardlib2.EMB); first-pass art, tweak individual recipes as needed.

## Tool status
Manager tool in tool/ is built (see README). Run `python tool/selftest.py` after changes. Custom animations live in data/animations/*.json and are
registered into sprites/gen_uv.py via sprites/custom_anims.py.

## Godot and export
**Read godot/CLAUDE.md before touching anything under godot/ or when adding players, animations, cards or packs (it holds the rules: folders, data contract, animation flow, states, input).**
`godot/` is the Godot 4 project. `tool/export_game.py` (Export to game button in the tool's tab strip) writes `godot/data/` and `godot/assets/` (git-ignored, generated). GDScript is untested: Godot is not installed in the container. Tracked: scripts/ (one folder per feature: core, packs, cards, players + players/states, debug), shaders/, scenes/, project.godot, assets/pitches/ (generated by the stadiums step, tracked), scenes/stadium + scripts/stadium. New Godot code goes in its own feature folder, never the scripts or scenes root (scenes/<feature>/ mirrors scripts/<feature>/). Player state machine: scenes/players/player.tscn with states as child nodes of StateMachine, editable in the inspector (PlayerState base node has clip / event_transitions / go_to_when_clip_ends exports; scripts in scripts/players/ and states/). The user also codes in Godot, so new states must stay inspector-friendly (@export, class_name, no hard-wiring). Player cards are modular: shared layers + one face per player, text/stats drawn live in Godot, shaders/, scenes/, project.godot.
Other tables now: packs, pack_odds, pack_pools (Packs tab, packs/packlib.py, packs/opening.py). Skill card face is the player-card style (cardlib2.card).
