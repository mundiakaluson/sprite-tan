# Godot project rules (read before changing anything in godot/, and when adding players, clips, cards or packs)

The user also writes Godot code and edits scenes in the editor, so everything must stay editor-friendly: `@export` for settings, `class_name` for
reusable scripts, scenes you can open and see something in. Godot is not installed in the container: nothing here has been run by Claude.
After a change, say what to test and ask the user to paste the Output panel if something fails. Godot version in use: 4.7 (project targets 4.2+).

## Layout (no loose files in a root)
- `scripts/<feature>/` and `scenes/<feature>/` mirror each other: `core`, `packs`, `cards`, `players` (+ `players/states`), `debug`. A new feature gets its own folder in both.
- `shaders/` tracked. `animations/` tracked but GENERATED (see below). `assets/pitches/` hand-made, tracked.
- `assets/*` (except pitches) and `data/` are generated by the manager tool's Export to game button (`tool/export_game.py`) and git-ignored. Never edit them by hand.

## Data
- `Data` is a static class (`scripts/core/data.gd`, no autoload, so @tool scripts and editor previews work): `Data.table`, `Data.row`, `Data.tex`, `Data.rules`, `Data.anims`.
- CSV columns are a contract with the tool: add columns, never rename or reorder. All values are Strings; convert with `Data.num` / `Data.inum`.
- Anything tweakable (stats, odds, speeds, flows) belongs in a CSV in the repo `data/`, not in a script constant. Script constants marked "placeholder" are to move into data.

## Players and animation
- `scenes/players/player.tscn`: Sprite (passive picture), AnimationPlayer (one Animation per sprite sheet), AnimationTree (flow graph with arrows between clips), StateMachine (gameplay states).
- `PlayerSprite` never animates itself. The AnimationPlayer sets its `sheet` and `frame_index`; `direction` is set by code (`Player.face_vector`).
- Animations are generated: add a clip by baking its sheet (tool: Animations tab / Base animations tab), then press Export. It appears in the Animation panel and in the flow graph.
- Arrows between clips come from `data/animation_flow.csv` (from, to, mode=auto; one outgoing arrow per clip). The export regenerates `animations/player_library.tres` and
  `animations/player_flow.tres` every time, so edit the CSV (tool: Other tables), NOT the graph in Godot. Commit the regenerated files.
- Gameplay states are child nodes of `StateMachine` (name = state name). Base node `PlayerState` has `clip`, `event_transitions`, `go_to_when_clip_ends`; scripts only override `_on_*` functions.
  New state = new node, or a script extending `PlayerState` with a `class_name` and `@export`ed settings. Do not hard-wire state names in other scripts beyond the ones in the scene.
- States ask for clips with `player.play_clip(name)`; do not touch AnimationPlayer or the sprite from states. Orders to players are events: `player.move_to`, `player.play_action`, `player.send_event`.
- Adding a PLAYER = a row in `data/players.csv` (look columns) + Export (writes `assets/looks/<id>.png` and `assets/faces/<id>.png`). No scene or script change.

## Cards
- Player cards are modular: shared layers per rarity / foil style, one face image per player, text and stats drawn live from the row (`PlayerCard`, `PixelText`, `data/card_rules.json`). Never bake stats into images.
- Skill cards are one exported image each (unique emblem art) plus tooltips; adding a card = a row in `cards.csv` + a recipe in `cards/recipes.py` + Export.

## Input
- Keys and mouse are Input Map actions in `project.godot`. Scripts use action names only (`is_action_pressed("play_kick")`). New control = new action, never a hard-coded key.

## Editor previews
- Scripts with previews are `@tool`. In @tool code never use autoloads, guard editor-only work with `Engine.is_editor_hint()`, and keep previews harmless in game.

## GDScript pitfalls already hit here
- Do not declare members that Node/Sprite2D already have (`frame`, `name`, `offset`...). Do not call static functions on instances. Avoid parameter names that shadow Node members.
- `Data.tex` falls back to reading the PNG when Godot's import is invalid; keep using it instead of `load()` for exported art.

## When you change something here
Update `godot/README.md`, `docs/DECISIONS.md`, `data/progress.csv`, the Claude Docs design document (14a/14b), and this file if a rule changes. Run `python tool/selftest.py` and the export.
